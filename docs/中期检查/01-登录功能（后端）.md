# 登录功能（后端）

**优先级：重要。** 它是所有受保护课堂功能的入口，但本项目的业务核心是考勤，见[考勤签到与自动缺勤](02-考勤签到与自动缺勤【核心】.md)。

## 1. 功能简介

本功能验证用户的校园账号、密码和所选身份，成功后生成 12 小时有效的随机 Token。后续 API 通过 Token 识别用户，再按角色、班级或学院范围授权。

对应的真实代码：

- `server/src/main/java/cn/zhixu/controller/ApiController.java`：接收 HTTP 请求；
- `server/src/main/java/cn/zhixu/service/SchoolService.java`：完成登录校验和 Token 签发；
- `server/src/main/java/cn/zhixu/security/AuthFilter.java`：拦截并认证后续受保护请求；
- MySQL 表 `users`、`tokens`：保存密码哈希与 Token 摘要。

## 2. 请求与响应

浏览器向 `POST /api/v1/auth/login` 发送：

```json
{
  "account": "20260101",
  "password": "用户输入的密码",
  "role": "student"
}
```

成功响应的 `data` 包含 Token 和不含密码字段的当前用户资料：

```json
{
  "token": "随机会话令牌",
  "user": { "id": 1, "account": "20260101", "name": "林同学", "role": "student" }
}
```

> 文档不记录演示账号、密码或本机数据库配置。

## 3. 执行过程

1. `ApiController.login(...)` 接收 JSON 请求，同时读取客户端地址并调用 `school.login(...)`。
2. `SchoolService.login(...)` 校验账号、密码长度；按客户端地址实行“一分钟最多 15 次”的失败尝试限制。
3. 服务从 `users` 查询启用账号，使用 BCrypt 的 `encoder.matches(...)` 比较明文输入与 `password_hash`。
4. 服务核对请求中的 `role` 是否等于数据库中的角色，防止把学生账号当教师身份使用。
5. 校验成功后，服务生成 32 字节随机 Token，只将 `SHA-256(Token)`、用户 ID 和 12 小时过期时间写入 `tokens`；原 Token 仅通过本次响应交给浏览器。
6. 浏览器请求其他 `/api/v1/**` 接口时，`AuthFilter` 读取 `Authorization: Bearer Token`，对 Token 再做哈希并查询未过期会话，把用户资料写入 request attribute；找不到则返回 401。
7. 用户点击退出时，`POST /api/v1/logout` 删除当前 Token 的摘要，令该会话立即失效。

## 4. 核心代码讲解

`SchoolService.login(...)` 是核心业务方法。源代码内已经标注三段关键逻辑：输入边界校验、密码哈希校验、随机 Token 的摘要存储。它的职责是业务判断，不直接处理 HTTP 响应。

`AuthFilter.doFilterInternal(...)` 是统一认证入口。它只放行健康检查与 `/auth/` 公开接口，其余 API 必须携带有效 Bearer Token；因此控制器中的课堂、考勤、请假等方法可以基于已认证用户继续做权限判断。

## 5. 可向老师说明的设计点

- **分层**：Controller 接请求，Service 处理登录规则，Filter 处理统一认证，Repository/JDBC 访问 MySQL。
- **密码安全**：数据库保存 BCrypt 哈希，不保存可读密码。
- **会话安全**：Token 原文不入库，丢失或退出后可在服务端失效。
- **权限边界**：登录只证明身份；每个业务接口仍使用当前用户的角色、班级、学院做二次授权。
