# 登录界面渲染（前端）

## 1. 功能简介

本功能显示知序课堂的登录页，收集“身份、学号/工号、密码”，调用后端登录接口，并在成功后进入相应角色的课堂工作台。

对应的真实代码：

- `server/src/main/resources/static/index.html`：页面容器和脚本加载顺序；
- `server/src/main/resources/static/auth.js`：登录页 HTML 渲染、输入状态和表单校验提示；
- `server/src/main/resources/static/bridge.js`：登录请求、Token 保存、退出和首次加载课堂数据；
- `server/src/main/resources/static/auth.css`：登录页视觉样式与移动端适配。

## 2. 页面首次打开

`index.html` 依次加载 `auth.js`、`app.js`、`bridge.js` 和 `reference-data.js`。最后执行的 `bridge.js` 会先检查浏览器是否已有 Token：

1. 有 Token 时调用 `GET /api/v1/me` 验证会话；验证成功就调用 `signedIn(...)` 加载课表和课堂数据。
2. 没有 Token 或 Token 过期时调用 `renderAuth()`，显示登录表单。

登录表单由 `auth.js` 中的 `authLogin()` 生成，包含角色选择、账号输入框、密码输入框、“记住登录状态”和错误提示区域。密码框支持显示/隐藏，但页面不会把密码写进持久化存储。

## 3. 点击“登录”的执行过程

1. 表单触发 `handleAuthLogin(event)`；该方法先 `preventDefault()`，避免浏览器刷新页面。
2. 登录按钮暂时禁用，避免用户重复点击导致重复请求。
3. 方法调用通用 `api('/auth/login', 'POST', ...)`，将账号、密码和当前选择的角色发送给后端。
4. 后端成功返回 Token 后，前端先清除旧 Token，再根据“记住登录状态”写入 `localStorage` 或 `sessionStorage`。
5. `signedIn(user)` 保存当前用户资料、选择对应角色首页，并依次读取课表和课堂数据，最后渲染工作台。
6. 如果接口返回错误，`authError(...)` 在登录页展示服务端错误信息，按钮恢复可点击状态。

## 4. 退出登录

顶部退出按钮调用 `logoutAuth()`：先请求后端删除 Token，再清除浏览器中的 Token、SSE 连接和页面内存数据。即使网络请求失败，本地页面也不会继续保持登录状态。

## 5. 可向老师说明的设计点

- **界面和网络分开**：`auth.js` 只负责页面状态与渲染；`bridge.js` 负责调用 API 与保存会话。
- **前端不判定密码**：密码是否正确只能由后端 BCrypt 校验，浏览器只呈现结果。
- **会话恢复**：刷新页面后会先用 `/me` 验证已保存 Token，而不是仅相信本地角色名称。
- **可用性**：提交时禁用按钮、错误可见、支持移动端样式和键盘提交。
