# ⭐ 考勤签到与自动缺勤（核心功能）

**优先级：核心。** 本项目围绕“课次”记录每个学生的签到结果；课后 30 分钟仍未签到且无有效请假的学生，会被自动记为缺勤。

## 真实代码入口

- `ApiController.checkIn(...)`：`POST /lesson-sessions/{sid}/check-in` 的 HTTP 入口；
- `SchoolService.checkIn(...)`：学生点击签到后的事务逻辑；
- `SchoolService.attendanceAt(...)`：根据课次开始时间判定 `PRESENT` 或 `LATE`；
- `SchoolService.finalizeAbsences(...)`：补写未签到学生的 `ABSENT`；
- `SchoolService.scheduleNextAbsenceCheck(...)`：只安排下一次应执行的缺勤检查；
- `SchoolService.changeAttendance(...)`：教师修正单个学生的考勤状态；
- MySQL 表 `attendance`：以 `(session_id, student_id)` 保证每人每课次只有一条最终记录。

## 学生签到流程

1. 前端请求签到接口，并随 Bearer Token 传递当前身份。
2. 服务读取课次，确认当前用户是该课程班级的学生，并确认当前时间在允许签到窗口内。
3. `attendanceAt(...)` 用服务端时间与 `start_at` 比较：正常窗口内写入 `PRESENT`，迟到窗口内写入 `LATE`。
4. 使用带唯一键的写入方式保存到 `attendance`，避免重复点击产生多条记录。
5. 控制器通过 SSE 向同课次页面发送 `refresh` 事件，教师座位图和学生页面刷新。

## 自动缺勤流程

1. 服务启动时 `initializeAbsenceSchedule()` 查询下一节需要处理的课。
2. `scheduleNextAbsenceCheck()` 把一次任务精确安排在该课开始后 30 分钟，而不是每分钟扫描全部课程。
3. 到时间后 `runScheduledAbsenceCheck()` 调用 `finalizeAbsences()`。
4. SQL 找出该班所有学生，为没有考勤记录、也没有已批准请假的学生插入 `ABSENT`。
5. 当前课次处理完毕后，程序再次安排下一节课的检查；因此凌晨运行时不会空转扫描。

## 教师修正与请假关系

教师可以通过 `changeAttendance(...)` 纠正某个学生的状态。已批准的请假由 `leave_targets` 关联具体课次，在自动补缺勤时会被排除，避免“请假”和“缺勤”同时产生。

## 向老师讲解的一句话

“考勤以课次和学生为联合唯一键；点击签到是即时写入，缺勤由开课 30 分钟后的单次定时任务补齐，避免持续扫描数据库。”
